# 问题解决报告 - 数据库字段缺失

## 问题描述

测试第 18 个接口（`POST /railway/parts/auto_segment`）时出现错误：

```
column item_info.parent_num does not exist
```

## 问题分析

### 1. 表面原因
数据库表 `parts.item_info` 中缺少 `parent_num` 和 `son_num` 两个字段，但代码的 ORM 模型中定义了这些字段。

### 2. 根本原因
在 `csrcqsf/settings.py` 文件的第 104 行，`get_async_pg_dsn()` 方法硬编码了数据库 IP 地址：

```python
# 错误的代码
def get_async_pg_dsn(self):
    return f"postgresql+asyncpg://{self.pg.user_name}:{quote_plus(self.pg.password)}@192.168.100.8:{self.pg.port}/zcsf"
```

这导致应用连接到了 `192.168.100.8` 数据库，而不是配置文件中指定的数据库地址。

### 3. 影响范围
- 所有使用异步数据库连接的接口都会受影响
- 特别是涉及 `Items` 模型查询的接口
- 包括但不限于：
  - `/railway/parts/auto_segment` (第 18 个接口)
  - `/sgo/sgo/inquery/list` (第 27 个接口)
  - 其他配件管理相关接口

## 解决方案

### 已完成的修复

#### 1. 修复硬编码问题
修改 `csrcqsf/settings.py` 第 104 行：

```python
# 修复后的代码
def get_async_pg_dsn(self):
    return f"postgresql+asyncpg://{self.pg.user_name}:{quote_plus(self.pg.password)}@{self.pg.url}:{self.pg.port}/zcsf"
```

现在使用 `self.pg.url` 动态获取数据库地址，而不是硬编码。

#### 2. 创建修复脚本
创建了两个数据库修复脚本：
- `fix_db_columns.py` - 用于当前配置的数据库
- `fix_db_columns_production.py` - 用于生产数据库（192.168.100.8）

### 需要执行的操作

#### 步骤1：在生产数据库上添加字段

**选项A：使用 Python 脚本**
```bash
# 1. 编辑 fix_db_columns_production.py，填入数据库连接信息
# 2. 运行脚本
source .venv/bin/activate
python fix_db_columns_production.py
```

**选项B：直接执行 SQL**
```sql
-- 连接到 192.168.100.8 的 PostgreSQL
\c zcsf

-- 添加字段
ALTER TABLE parts.item_info 
ADD COLUMN IF NOT EXISTS parent_num INTEGER NOT NULL DEFAULT 0;

ALTER TABLE parts.item_info 
ADD COLUMN IF NOT EXISTS son_num INTEGER NOT NULL DEFAULT 0;
```

#### 步骤2：重启应用
```bash
# 重启应用以使代码更改生效
sudo systemctl restart your-app-service
```

## 验证

执行以下 SQL 验证字段已添加：

```sql
SELECT column_name, data_type, is_nullable, column_default
FROM information_schema.columns
WHERE table_schema = 'parts' 
  AND table_name = 'item_info'
  AND column_name IN ('parent_num', 'son_num');
```

应该看到：
```
 column_name | data_type | is_nullable | column_default 
-------------+-----------+-------------+----------------
 parent_num  | integer   | NO          | 0
 son_num     | integer   | NO          | 0
```

## 预防措施

### 1. 代码层面
- ✅ 避免硬编码数据库连接信息
- ✅ 使用配置文件管理所有环境变量
- 建议：引入 Alembic 进行数据库迁移管理

### 2. 部署流程
- 在开发环境测试新字段后再部署到生产环境
- 使用数据库迁移脚本而不是手动修改表结构
- 保持代码模型和数据库结构同步

### 3. 监控
- 添加数据库连接监控
- 记录所有数据库错误日志
- 定期检查表结构一致性
