# 修复数据库字段缺失问题

## 问题描述
错误信息：`column item_info.parent_num does not exist`

模型中定义了 `parent_num` 和 `son_num` 字段，但数据库表中没有这些列。

## 根本原因
在 `csrcqsf/settings.py` 中，`get_async_pg_dsn()` 方法硬编码了数据库 IP 地址 `192.168.100.8`，而不是使用配置中的 `self.pg.url`。这导致应用连接到了错误的数据库实例。

**已修复**: 现在使用 `self.pg.url` 动态获取数据库地址。

## 解决方案

### 步骤1：修复代码（已完成）
`csrcqsf/settings.py` 中的硬编码 IP 已修复，现在使用配置中的数据库地址。

### 步骤2：在生产数据库上添加字段

**方法1：使用 Python 脚本（推荐）**

1. 编辑 `fix_db_columns_production.py`，填入正确的数据库连接信息：
```python
DB_USER = "postgres"  # 修改为实际用户名
DB_PASSWORD = "your_password"  # 修改为实际密码
DB_HOST = "192.168.100.8"
DB_PORT = "5432"
DB_NAME = "zcsf"
```

2. 运行脚本：
```bash
source .venv/bin/activate
python fix_db_columns_production.py
```

**方法2：直接执行 SQL**

连接到 PostgreSQL 数据库（192.168.100.8），执行以下 SQL：

```sql
-- 连接到数据库
\c zcsf

-- 添加 parent_num 字段
ALTER TABLE parts.item_info 
ADD COLUMN IF NOT EXISTS parent_num INTEGER NOT NULL DEFAULT 0;

-- 添加 son_num 字段
ALTER TABLE parts.item_info 
ADD COLUMN IF NOT EXISTS son_num INTEGER NOT NULL DEFAULT 0;

-- 验证
SELECT column_name, data_type, is_nullable, column_default
FROM information_schema.columns
WHERE table_schema = 'parts' 
  AND table_name = 'item_info'
  AND column_name IN ('parent_num', 'son_num');
```

### 步骤3：重启应用

```bash
# 如果使用 systemd
sudo systemctl restart your-app-service

# 或者手动重启
pkill -f "uvicorn csrcqsf.app:app"
# 然后重新启动应用
```

## 验证

执行后，可以通过以下 SQL 验证：

```sql
SELECT column_name, data_type, is_nullable, column_default
FROM information_schema.columns
WHERE table_schema = 'parts' 
  AND table_name = 'item_info'
  AND column_name IN ('parent_num', 'son_num');
```

应该看到两个字段都存在。

## 预防措施

为了避免将来出现类似问题，建议：

1. 使用 Alembic 进行数据库迁移管理
2. 在开发环境测试新字段后再部署到生产环境
3. 保持模型定义和数据库结构同步
