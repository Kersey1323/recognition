# 项目代码结构说明

## 📁 代码分层架构

项目采用经典的三层架构：

```
csrcqsf/
├── services/          # 服务层 (API路由定义)
├── biz/              # 业务逻辑层
├── data/             # 数据访问层
└── models/           # 数据模型层
```

---

## 🔄 请求处理流程

```
HTTP请求 
  ↓
services/ (路由层)
  ↓
biz/ (业务逻辑层)
  ↓
data/ (数据访问层)
  ↓
models/ (ORM模型)
  ↓
数据库/外部服务
```

---

## 📂 详细目录说明

### 1. services/ - 服务层（API路由）

**职责**: 定义API接口、参数验证、调用业务逻辑

**文件**:
- `parts.py` - 配件相关接口
- `sgo.py` - SGO系统集成接口
- `doc_parse.py` - 文档管理接口
- `images.py` - 图像处理接口

**示例**:
```python
# csrcqsf/services/parts.py
@parts_router.post('/index_rebuild')
async def rebuild_parts_pic_index():
    # 仅调用业务逻辑，不包含具体实现
    return await RailwayPartsManager.rebuild_pic_index()
```

---

### 2. biz/ - 业务逻辑层

**职责**: 实现具体的业务逻辑、算法调用、数据处理

**目录结构**:
```
biz/
├── railwayparts/          # 配件相关业务
│   ├── parts.py          # 配件管理核心业务逻辑
│   ├── milvus.py         # Milvus向量检索
│   ├── auto_processor.py # 自动化处理
│   └── api_models.py     # API模型定义
├── reconstruction/        # 3D重建业务
│   ├── colmap_processor.py
│   └── gaussian_trainer.py
├── segment.py            # 图像分割业务
├── sgo.py               # SGO集成业务
└── doc_parse.py         # 文档解析业务
```

**示例**:
```python
# csrcqsf/biz/railwayparts/parts.py
class RailwayPartsManager:
    @classmethod
    async def rebuild_pic_index(cls):
        # 具体的业务逻辑实现
        async with SessionLocal() as session:
            await SgoItemImages.make_image_unindexed(session=session)
            images = SgoItemImages.get_all_image(session=session)
            await MilvusManager.rebuild_collection([image async for image in images])
            await SgoItemImages.make_image_indexed(session=session)
            await session.commit()
```

---

### 3. data/ - 数据访问层

**职责**: 数据库连接、会话管理、基础查询

**文件**:
- `pg.py` - PostgreSQL连接和会话管理
- `milvus.py` - Milvus向量数据库连接
- `minio.py` - MinIO对象存储客户端

**示例**:
```python
# csrcqsf/data/pg.py
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession

engine = create_async_engine(DATABASE_URL)
SessionLocal = sessionmaker(engine, class_=AsyncSession)
```

---

### 4. models/ - 数据模型层

**职责**: ORM模型定义、数据库表映射、基础CRUD方法

**目录结构**:

models/

## 🎯 核心业务类说明

**主要方法**:

- `rebuild_pic_index()` - 重建索引
- `search()` - 综合检索

---

### MilvusManager
**位置**: `csrcqsf/biz/railwayparts/milvus.py`

**职责**: Milvus向量数据库管理

**主要方法**:

## 📝 代码阅读顺序建议

### 理解一个接口的完整流程

1. **services/** - 看接口定义和参数
2. **biz/** - 看业务逻辑实现
3. **models/** - 看数据模型定义
4. **data/** - 看数据库操作

### 示例: 理解 index_rebuild 接口

```
1. csrcqsf/services/parts.py (第146行)
   ↓ 调用 RailwayPartsManager.rebuild_pic_index()
   
2. csrcqsf/biz/railwayparts/parts.py (第529行)
   ↓ 调用 SgoItemImages.make_image_unindexed()
   ↓ 调用 MilvusManager.rebuild_collection()
   
3. csrcqsf/models/sgo.py
   ↓ 数据库操作
   
4. csrcqsf/biz/railwayparts/milvus.py
   ↓ Milvus向量操作
```

## 🔧 开发建议

### 添加新接口时

1. 在 `services/` 定义路由
2. 在 `biz/` 实现业务逻辑
3. 在 `models/` 定义数据模型（如需要）
4. 在 `data/` 添加数据访问方法（如需要）

### 修改现有接口时

1. 先找到 services/ 中的路由定义
2. 追踪到 biz/ 中的业务逻辑
3. 理解完整流程后再修改
4. 注意修改可能影响的其他接口
