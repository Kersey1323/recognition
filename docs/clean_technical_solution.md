# 动车配件图像识别与三维数字孪生系统技术架构方案

## 一、 系统架构概述
本系统针对动车零配件的智能化识别和三维重建需求进行设计。核心架构采用视觉大模型进行图像特征提取，结合 2DGS (二维高斯溅射) 技术进行三维重建。系统主要解决相似配件精确检索、复杂工业背景去除、高质量三维网格导出以及大并发任务调度等工程问题。

## 二、 核心视觉特征模型的迭代与横向选型论证
在系统的上一版本（V1.0）中，核心图像特征提取依赖于 ResNet-34 卷积神经网络。随着工业库容复杂度的增加，当前版本全面迭代为基于 Vision Transformer 的自监督大模型 DINOv2-Large。本节归纳模型迭代原因及选型对比。

### 2.1 早期版本局限性：淘汰 ResNet-34 的原因
在旧版本中，主要通过截取 ResNet-34 的全局平均池化层（GAP）输出 512 维隐空间向量。
- **原有优势**：作为经典 CNN，其单图前向推断延迟保持在十毫秒级，适合在纯 CPU 环境下作轻量提取比对。
- **业务局限性暴露**：
  1. **空间特征降采样折损**：卷积网络的下采样及 GAP 池化操作会抹去图像高频细节。对于具有微小差异（如螺距或极细倒角之差）的非标准零件，提取的特征区分度过低。
  2. **监督学习的形状偏置**：ResNet 神经元激活分布容易向物体的宏观轮廓偏斜。在面对机车表面强烈的高光白斑和块状油污遮蔽时，同类零件的特征余弦距离被剧烈拉低，引发错误分类碰撞。

### 2.2 业界主流视觉基座横向对比验证
为解决以上阻碍，研发层面引入了当前具有代表性的先进视觉基座，包括 ConvNeXt V2、CLIP 与 Swin-Transformer 进行对比：
1. **ConvNeXt V2 (768维)**：
   - 评估：吸收 ViT 构架特性的现代 CNN，高并发吞吐量表现最优。但对于严重透视偏转与零样本视角的畸变容忍度，受限于卷积权重的滑动窗口固有属性，泛化表现一般。
2. **OpenAI CLIP (512/768维)**：
   - 评估：主要侧重图文跨模态语义对齐。若业务需求为指令化文本检索（输入文本召回图片）则表现优异；但在纯几何外观校验（同型号紧固件对比）中，由于训练损失偏重宏观语义关联，细节物理纹理的量化鉴别力不足。
3. **Swin-Transformer (1024维)**：
   - 评估：通过移动窗口解决全图注意力显存平方增加的问题，是 4K/8K 级超清表面探伤的首选。但在单体配件 224x224 或 512x512 裁剪区域扣图入库的流水线内，其计算性价比无明显优势。

### 2.3 当前版本定型：部署 DINOv2-Large (1024维)
综合论证下，系统最终选定 DINOv2 作为推断链路的主节点，符合特定的工程与物理条件：
1. **多头注意力抗局部噪声**：DINOv2 的注意力网络能动态稀释由金属反光光斑或油渍产生的像素干涉，自动将高权重系数聚焦于相对固定的螺纹、倒角与刻线机械结构上。
2. **三维空间正交性维持**：基于局部到全局裁剪预抽取的对比学习，迫使网络内化学习目标的物理三维深度分布。输入镜头的相对角度和发生平移倾斜时，输出的 1024 维向量仍能维持流形对齐，降低跨视角的距离偏移。
3. **高稳定细粒度（Fine-grained）表征**：近源结构分类精度高。保障后端请求 Milvus 向量库执行 L2 欧几里德距离比对时，实现各配件物料 SKU 的准确分簇。

## 三、 背景分割与图像提纯 (SAM)
为防止操作背景（如工作台、手套）污染图像特征，系统引入 SAM (Segment Anything Model) 实现自动化前景提取。

### 3.1 自动化处理管线
系统通过 `AutoPartProcessor` 执行端到端背景白化处理，步骤如下：
1. **点阵采样**：使用 `SamAutomaticMaskGenerator` 全自动生成网格初始锚点。
2. **多尺度推理**：SAM 并行输出全场景的候选图层。
3. **连通域面积过滤**：在配件为主体拍摄的先验条件下，程序按照像素面积降序排序，选取最大连通域作为前景目标。
4. **反选与白化背景**：将获取的配件边界掩码外区域的 RGB 值统一覆写为 (255, 255, 255)，根据 Bounding Box 裁剪输出，并送至 MinIO 存储及下游 DINOv2 流水线。

### 3.2 置信度清洗参数
在流转入库前，程序执行过滤机制：
- 剔除交并比阈值 `pred_iou_thresh < 0.88`。
- 剔除稳定性分数 `stability_score_thresh < 0.95` 的掩码。
- 若中心被误判镂空，系统执行 OpenCV 闭运算填充内侧孔洞，确保提取物件整体性。

## 四、 三维重建管线 (2DGS + SuGaR)
系统须导出 `.obj` 或 `.fbx` 标准多边形网格格式，因此放弃 3D Gaussian Splatting (3DGS)，全面采用 2DGS 技术。

### 4.1 3DGS 方案的局限性
3D 椭球体主要用于体积拟合，缺乏法向约束，会在物体表面或内部产生悬浮的交叉点和孔洞。在通过 Marching Cubes 提取多边形网格时，这会导致最终 Mesh 出现拓扑破损与噪声。

### 4.2 2DGS 表面对齐机制
2DGS 将高斯体积参数压缩为 2D 盘片，强制应用于物理平面拟合：
1. **深度一致性约束 (Depth Distortion Regularization)**：迫使位于同一射线锥体的多个高斯圆盘在空间深度上靠拢，消除悬浮游离点。
2. **法向量对齐 (Normal Consistency Penalty)**：约束光栅化渲染出的像素法向需与该 2D 圆盘自身的 3D 旋转法线平行。
3. **网格提取 (SuGaR)**：圆盘紧缩贴合物理表面后，系统使用泊松表面重建算法 (Poisson Surface Reconstruction) 提取平滑、拓扑结构完整的 `.obj` 网格，供 WebGL 或工业引擎原生调用。

## 五、 微服务架构与数据库拓扑
系统采用 FastAPI + K8s 的云原生架构设计，底层划分为数据存储域、推断微服务群和重建图形节点。

### 5.1 数据存储机制
- **PostgreSQL 业务库**：负责配件基础表设计与系统事务管理（ACID），避免冗余垃圾资产记录。
- **Milvus 向量检索库**：采用 HNSW 索引架构处理高维向量。配置多分区策略提高检索响应速度（百毫秒级）。根据模型隔离策略，系统自动进行表级路由调度（例如使用单独的 `railway_parts_resnet_512L` 和 `railway_parts_dinov2_1024L` 分流检索）。
- **MinIO 对象存储群**：通过分布式 Erasure Code 冗余协议，存放原始图、切割白底图及导出的三维模型文件；通过前端预签名链接减轻服务器下行带宽。

### 5.2 大并发 3D 渲染削峰策略
应对大量 2DGS 的大显存消耗场景：
1. 分配独立的外部消息队列（例如 Celery worker），单台运算节点锁死最大并发数。
2. 任务状态登记在 PostgreSQL，CUDA 重建进程发生 OOM 时隔离抛停，确保主 Web 接口常驻运转。
3. 完成标准网格导出后，任务流执行热清理自毁命令移除原始 COLMAP 以及 2DGS 迭代期生成的数 G 缓存，保证服务器存储与 Inode 可维护性。

## 六、 模型抽取接口解耦模式
系统通过基类抽象解决了后续引入类似 CLIP、Swin-Transformer 或 ConvNeXt 模型的低效重构问题。

**方案要点：**
- 定义统一的 `BaseExtractor` 接口（声明了 `extract_feature`、`get_dimension`、`get_collection_name` 方法）。
- DINOv2 与 ResNet-34 实例化该接口，在各自内部消化卷积/池化池或 Token Slice 处理方式的差异，最终对外流出统一的 Numpy 向量及绑定的 Milvus 表名。
- FastAPI 层仅初始化该抽象对象的特征转换方法，彻底隔离底层异构物理网络。

## 七、 扩展与多模态匹配
引入基于 PP-OCRv5 (RapidOCR) 管线提取金属件边缘的序列号与丝印。辅以 Sentence-Transformers 提取 512 维隐语义文本向量并入 Milvus 文本库进行检索。最终检索结果将与 DINOv2 的视觉余弦打分合并，通过二路交叉定位减少孤立视觉造成的歧义。
