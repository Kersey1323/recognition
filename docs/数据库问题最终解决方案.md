# 数据库问题最终解决方案

## 问题总结

应用报错 `column item_info.parent_num does not exist` 和 `column item_info.image_index_num does not exist`

## 根本原因

经过排查，发现有**三个 PostgreSQL 数据库实例**，表结构完整性不同：

| 数据库地址 | 端口 | 连接状态 | 表结构完整性 | 配件数量 |
|-----------|------|---------|------------|---------|
| 192.168.100.126 | 5432 | ❌ 无法连接 | 未知 | - |
| 192.168.100.8 | 5432 | ✅ 可连接 | ⚠️ 部分字段缺失 | 78,740 |
| 192.168.100.2 | 5432 | ✅ 可连接 | ✅ 完整 | 78,740 |

### 192.168.100.8 缺失的字段
- ❌ `image_index_num` - 图片索引数量
- ❌ `feature_index_num` - 特征索引数量

### 192.168.100.2 完整的表结构（18个字段）
```
✓ item_name
✓ item_code
✓ obj_url
✓ height
✓ long
✓ width
✓ parent_item_id
✓ id
✓ created_by
✓ updated_by
✓ time_created
✓ time_updated
✓ size_str
✓ item_type
✓ parent_num          ← 之前缺失
✓ son_num             ← 之前缺失
✓ image_index_num     ← 之前缺失
✓ feature_index_num   ← 之前缺失
```

## 解决方案

### 已完成的修复

**修改 `csrcqsf/settings.py`**，将数据库地址指向有完整表结构的数据库：

```python
ai_settings = AISettings()

# 修复数据库地址：使用有完整表结构的数据库
# 192.168.100.126 无法连接
# 192.168.100.8 缺少 image_index_num 和 feature_index_num 字段
# 192.168.100.2 有完整的表结构 ✓
ai_settings.pg.url = "192.168.100.2"
```

### 需要执行的操作

**重启应用**以使配置生效：

```bash
# 方法1: 如果使用 systemd
sudo systemctl restart your-app-service

# 方法2: 手动重启
# 1. 停止当前进程
pkill -f "uvicorn csrcqsf.app:app"

# 2. 启动应用
cd /home/ubuntu/project-train/recognition
source .venv/bin/activate
uvicorn csrcqsf.app:app --host 0.0.0.0 --port 65432
```

## 验证
